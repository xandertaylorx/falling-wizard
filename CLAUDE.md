# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Falling Wizard: a Noita-style falling-sand wizard game in Rust + macroquad 0.4, macOS-first. **No asset files at runtime**: every pixel, the font, all sounds and the app icon are generated in code. The repo (github.com/xandertaylorx/falling-wizard, branch `main`) is public but **not open source** (all rights reserved, see `LICENSE`). The website `web/` is deployed by Vercel to https://fw.crooli.com on every push.

## Owner preferences (from past sessions)

- Push straight to `main` when a task is done; the owner asks for this every time.
- Keep verification light: one quick build plus at most a screenshot pass, not long test suites ("don't do too many tests").
- Don't cap or advertise the frame rate as 60 FPS. The sim steps at a fixed rate, but rendering runs at the display's refresh rate.
- Creative mode is the main focus when proposing features.

## Commands

```bash
cargo build --release                         # normal build (dev profile is also optimised)
cargo run --release                           # play
cargo run --release -- --mute                 # play without sound
cargo run --release -- --bench                # headless sim benchmark + material behaviour checks (no window)
cargo run --release -- --autotest 22 <dir>    # scripted, muted tour: prints frame stats, saves screenshots to <dir>
cargo run --release -- --photos <dir>         # HUD-free tour that regenerates the website screenshots
cargo run --release -- --version | --update   # print baked commit / self-update now
python3 tools/make_icon.py                    # redraw assets/icon.png, AppIcon.icns, icon_*.rgba, web/img/{icon,favicon}.png
```

There are no unit tests or lints. The only check is a clean `cargo build --release` (keep it warning-free). The `--bench` flag runs `material_checks()` in `main.rs`, which are the closest thing to tests.

**Visual checks:** temporarily add an env-var hook in `run()` just before `app.frame(dt, script)` in `main.rs`, e.g. `if let Ok(dir) = std::env::var("FW_X") { ... app_shot(&format!("{dir}/a.png")) ... std::process::exit(0) }`, then run `FW_X=<scratch dir> ./target/release/falling-wizard --mute`.
- Trigger one-shot actions with an `AtomicU32` bit-flag `at(t)` helper. A `(now - t).abs() < 0.009` window misses frames.
- `app_shot` defers the PNG capture until after the frame is drawn, because capturing earlier gives black images.
- Always delete the hook before committing.

## Architecture

### Frame flow

`main.rs` runs an `App` holding a `Screen` state machine:
- Screens: Menu, Worlds, NewWorld, Play, Pause, Settings, Controls, Chat, Planets (the 3D planet carousel), Warp (portal travel), Rift (the black-hole trip) and Dead.
- Each frame, `App::frame` updates according to the screen, then draws the world via `Renderer::draw`, then the UI for that screen.
- `Game::update` (`game.rs`) runs the fixed-rate simulation: `world.step()`, `spells.step()`, `step_rifts()` and `fx.step()`, up to 3 steps per frame. Mobs, player, weather and the rest update per frame.

### World (`world.rs`)

An infinite world streamed through a fixed **window** of `WCX`×`WCY` chunks (`CHUNK` = 64 cells). The window is about 640×512 cells, with origin `ox`/`oy`.
- **Leaving the window:** `shift_to` recenters on the player. Chunks that leave are kept in `store` only if they're **dirty**, meaning edited.
- **Entering the window:** chunks come from `store` or are freshly generated by `gen.chunk()`. Both paths then call `void_chunk`.
- **Sleeping:** simulation runs in 16×16 sub-chunks that sleep when settled. `wake()` marks them active and marks the chunk dirty.
- **Cells:** each `Cell` (`cell.rs`) holds `mat`, `life`, `temp`, `shade`, `vel`, `clock` and `back`. `back` is the walk-through background layer for trees and plants. `world.wall` is the cave background wall, where 0 means open sky.
- **Coordinates:** all public APIs (`mat`, `get`, `set`, `place`, `set_back`, `set_wall`, `ignite_at`) take **global** coordinates. Only cells inside the window exist.

### Materials (`materials.rs`)

`Material` is `#[repr(u8)]` and its discriminants are written into save files. **Only append new materials at the end**, and update `LAST_MATERIAL`, which `saves.rs` uses to validate loaded bytes.
- Several property `match`es must be exhaustive: `kind`, `base_color` and `name`.
- The others need new entries as appropriate: `density`, `variation`, `emissive`, `burn`, `acid_rate`, `passable`, `solid` and `indestructible`.
- Material behaviour rules live in `world.rs` (`update_gas`, `update_fire`, liquids and so on).

### Worldgen and planets (`worldgen.rs`, `planets.rs`)

- **Generator:** `Generator::with_planet(seed, Planet)`. Earth is `Planet::earth()` at galaxy cell (0,0), and `Generator::new(seed)` is the same as Earth.
- **Planets:** `Planet::at(gx, gy)` gives the procedural planet in a galaxy cell (about 55% of cells have one), and `Planet::nearest` lists the closest ones.
- **Contents:** biomes, caves, ruins, volcanoes and geysers, sky isles and space.
- **Climate:** `Planet::climate()` gives oxygen, heat and atmosphere height; it's copied into `world.climate` and drives fire, freezing/evaporation (`weather_tick`), the atmosphere edge in `game.rs` and the sky. `Planet::sky_scene()` gives suns, bodies seen from orbit and nebula colour.
- **Portal structures:** `portals_near`, `portal_interior` and `portal_fill`. `PORTAL_HOME` is where the arrival portal on each planet sits.

### Game state (`game.rs`)

`Game` owns the world, player, fx, spells, mobs, weather, planet, portals, rifts, blights and save state.

Key flows:
- **Creating a world:** `with_options(WorldOptions)`. `apply_mode` turns on god mode, infinite flight and peaceful mobs in creative.
- **Portal travel:** `enter_planet`, triggered by `travel`.
- **Rift travel:** `arrive_through_rift`, triggered by `rift_travel`.
- **Chat:** `command()` handles `/tp`, `/time`, `/weather`, `/summon`, `/rift` and the rest. `suggest()` and the `COMMANDS` list drive the Minecraft-style completion.
- **Cross-system events:** these go through Vec "mailboxes" that the game drains each frame:
  - `spells.rifts_born`, `spells.rift_hits` and `spells.zaps` (lightning impacts, which drive `electrify`)
  - `spells.portal_hits`
  - `weather.strikes`
  - `fx.explosions`
  - The `sounds` vecs on game, spells and mobs, which `App` plays.
- **Rifts (`rift.rs`):** two black holes that spiral together merge into a `Rift`.
  - A Portal Wand bolt seals it: `closing` → `seal_fx`.
  - Another black hole touching it shatters it: `shatter` → `shatter_fx`, which spawns a `Blight`, a void wasteland of radius 475 that spreads with rays in `step_blights`.
  - Blights are also copied into `world.voids`, so chunks that load later get voided too. Conversion is deterministic, so redoing it is harmless.

### Saves (`saves.rs`)

Worlds live in `~/Library/Application Support/Falling Wizard/worlds/<slug>/`:
- `world.txt` holds `key=value` lines: options, planet, position and time, plus repeated `portal=`, `rift=` and `blight=` lines.
- `planet_<gx>_<gy>.bin` (magic `FWC1`) holds only the dirty chunks (`World::export` / `World::with_saved`).

Saving happens every 60 s, before warping, on Pause → Main Menu, and on Quit. `Game::load` rebuilds everything from these files. When you add persistent state, add it to `Game::save` and `Game::load`.

### Rendering (`render.rs`)

1. **CPU pass:** the CPU fills an albedo buffer and an emission buffer for the view, one pixel per cell, including sky, background walls, foliage, the void sky over blights, and lighting from emissive materials.
2. **Moving things:** fx, weather, mobs, spells and the player are drawn into the albedo buffer through `Canvas`.
3. **Post-effects:** black-hole lensing (`lens`) and rifts (`draw_rift`) are applied on top.
4. **GPU pass:** the GPU ray-marches light from the emission buffer, blurs it, and composites the result.
5. **Fine effects:** `Fx::draw_fine` then draws effects finer than a pixel in screen space: hair-thin rain, soft embers and curling wind streams. They're particles with `fine != 0`.

`View` maps world cells to screen space; `scale` is screen pixels per cell.

### Creatures (`mobs.rs`, `creatures.rs`)

- **Definitions:** `spec()` gives stats and AI type, and `size()` gives the hitbox.
- **Old sprites:** the ASCII sprites and palettes in `spec` are legacy and no longer drawn.
- **Art:** `creatures::paint(kind, &Anim)` draws each creature procedurally from body parts every frame into a `Pix` buffer, facing right, with a margin and an outline. `blit` mirrors it into the world. Corpses rotate the same art with `Pose::Dead`.
- **Behaviour:** this lives in `Mobs::update`. A shared AI branch per `Ai` type is shaped by per-species rules: stalk and pounce, ambush, pack circling, kiting, roosting, schooling, fleeing when wounded, and avoiding fire, cliffs and water.
- **Animation state:** `Mob` fields `pose`, `walk`, `st` (a behaviour timer), `attack_t` and `angry`.
- **Exceptions:** Worm and Dragon still use the segment drawing in `mobs.rs`.

### Other modules

- **`spells.rs`:** the 19 spells in `SPELL_BAR` (keys 1–0, -, =, Q, R, G, P, V, C, H), projectiles, black holes, tornadoes and the wind `gust`. Cards with `beam_after()` become held beams via `beam_tick` (lightning stream, flamethrower, frost breath, Heat Ray, Gravity Gun); `Storm` clouds rain and strike.
- **`weather.rs`:** the day clock (`daylight()`), sky states and particle spawning.
- **`ui.rs`:** the pixel font, HUD, planet sphere, chat and the menu widgets.
- **`audio.rs`:** synthesised sound effects (`Sfx`).
- **`updater.rs`:** compares the baked `FW_COMMIT` (from `build.rs`) against `git ls-remote`. It updates by running `curl …/install.sh | FW_NO_OPEN=1 FW_PROGRESS=1 bash` and parses `::total:N` and cargo's `Compiling` lines to show progress. `check()` re-checks on demand.

### Distribution

`web/install.sh` is the one-line installer. It:
1. Installs Rust if needed.
2. Clones or pulls the repo.
3. Builds the game.
4. Makes `/Applications/Falling Wizard.app` with `assets/AppIcon.icns`.
5. Adds a `falling-wizard` command.

There are no GitHub releases.

On Vercel, `vercel.json` (`outputDirectory: web`) and `.vercelignore` limit deploys to `web/`. Deployment uses the Vercel CLI as `tiztech` with scope `xander-taylors-projects`, because the Vercel MCP connector returned 403.

The window icon comes from the `include_bytes!` of `assets/icon_*.rgba` in `main.rs`'s `conf()`.
